# Scryfall API Portability Assistant – Test Plan

## Purpose

This document outlines the testing strategy for the Scryfall API Portability Assistant. The purpose of this test plan is to ensure the system remains reliable, accurate, secure, and performant for users accessing and exporting *Magic: The Gathering* card data from Scryfall.

This document serves as:

* a guide during implementation,
* a reference for future maintenance,
* and a living document for monitoring system quality over time.

---

# System Overview

## Application Components

### Frontend

* User query input interface
* Dataset preview interface
* Export selection (JSON or CSV)

### Backend

* Flask API server
* API endpoints for card retrieval and search
* Internal JSON restructuring pipeline
* Export generation system

### External Dependency

* [Scryfall API](https://scryfall.com/docs/api)

---

# Current API Endpoints

| Endpoint           | Purpose                                        |
| ------------------ | ---------------------------------------------- |
| `/card/{card}`     | Returns a single card by name                  |
| `/cards`           | Returns all cards                              |
| `/cards/random`    | Returns a random card                          |
| `/cards/search`    | Searches cards by name or oracle text          |
| `/cards/filter`    | Filters cards by color                         |
| `/cards/recommend` | Recommends cards based on color and mana value |

---

# Test Objectives

The primary testing objectives are:

* Ensure all API endpoints function correctly
* Verify exported JSON and CSV formats are valid and consistent
* Confirm transformed data matches the intended schema
* Detect malformed or invalid user queries safely
* Measure API performance under normal and heavy load
* Ensure exported datasets maintain data quality
* Identify and monitor security or abuse-related issues

# Monitoring, Alarms, and Actions

| Alarm                     | Trigger                                  | Action                              |
| ------------------------- | ---------------------------------------- | ----------------------------------- |
| API Failure               | Multiple failed Scryfall requests        | Log incident and notify maintainer  |
| High Latency              | Requests exceed 5 seconds                | Investigate bottlenecks             |
| Excessive Requests        | Large number of requests from one source | Rate limit or temporary block       |
| Export Failure            | Failed JSON/CSV generation               | Log export error                    |
| Schema Validation Failure | Export missing required fields           | Reject export and notify user       |
| Server Crash              | Flask server unavailable                 | Restart application and review logs |

# Continuous Testing & Maintenance

The test plan will remain active throughout development and deployment.

Planned ongoing testing includes:

* manual smoke testing after major changes,
* automated endpoint testing,
* schema validation during export,
* periodic performance testing,
* and monitoring external API dependency health.

Future improvements may include:

* Pytest integration for automated backend testing,
* CI/CD testing through [GitHub Actions](https://github.com/features/actions),
* automated JSON schema validation,
* and rate-limiting or authentication for hosted deployments.
